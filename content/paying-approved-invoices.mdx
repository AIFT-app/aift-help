# Paying Approved Invoices

Once supplier invoices are approved, the finance admin needs to pay them. AI Finance Team turns the approved, still unpaid invoices into a payment list you can download and take to your bank. This article is for the person who pays: the finance admin or the owner.

## Money never moves through AI Finance Team

A payment file is a proposal. You import it into your own netbank, check it there and sign it there, exactly as you would sign a transfer you typed by hand. Every Hungarian bank requires that signature after an import. AI Finance Team never holds your bank login and never sends a transfer.

An invoice counts as paid only when the bank transaction arrives and is matched to it, as today. Being in a payment file does not mark an invoice paid.

## Where it is

Open **Payment file** in the sidebar. It sits right under **Approvals**, because paying is a separate step after approving. You need the permission "Export payment file"; by default the client owner and the accountant admin have it. Your workspace admin can give it to anyone through a role or a per-member exception. See [Roles and Permissions](/roles-and-permissions).

## What you see

The tab lists every supplier invoice that is approved and still unpaid, grouped by the bank account that will pay it (one group per paying entity and currency). Each line shows:

- **Payee** and the invoice number, with a link to the invoice.
- **Payee account**: the account the money goes to, and its check state.
- **Due** and **Execution**: the payment date on the invoice, and the date the transfer is requested for. Today's date replaces a due date that has passed.
- **Amount**: what is still owed. For a partially paid invoice, the remaining balance.

Lines already written into a file are hidden. Switch **Show lines already in a file** on to see them, marked with the file number.

## The account check

Paying the wrong account is the most common invoice fraud, so every payee account has to be confirmed before it can go into a file. A person confirms it, or, where the company register check is switched on for your workspace, the register can confirm an account the first time it is seen.

- **Confirmed**: someone holding "Manage approvals" confirmed this account on the partner page, or the company register lists this account for the supplier's tax number. The line can be paid. Under the account the page says which of the two it was, with the date, and the downloaded spreadsheet carries the same in its last column.
- **First time seen**: this supplier's account has not been confirmed yet. Open the partner and confirm it after you checked it with the supplier.
- **Account changed**: the account on this invoice differs from the one that was confirmed before. The line stays blocked until someone confirms the new account. Call the supplier on a number you already know before you do.
- **No account**, **Invalid account**, **No verified partner**: the line cannot be paid yet; the reason and the next step are shown under it.

Blocked lines sit in their own group, "Cannot be included yet", with a link to the partner page.

Where the company register check is on, every line also shows what the register says about the account: listed since a date, not listed, or cannot be checked and why. A changed account is never confirmed by the register. It always waits for a person, and the register's answer is shown next to it so the decision is informed. "Not listed" is not proof of fraud: a bank has eight days to report a new account. See [Company register check](/company-register-check).

## Downloading the list

1. Tick the lines to pay in a group, or use **Select all in this group**.
2. If the entity has several accounts in that currency, choose the paying account.
3. Pick the format. **Spreadsheet (XLSX)** works with every bank. **Bank file (pain.001 XML)** is offered when the paying account's bank documents a pain.001 import. **Electra file (.HUF)** is offered on HUF groups at the banks that run an Electra-based netbank (K&H, Erste, MBH, Gránit). The line above the group says how far that import is verified.
4. Click **Download list (XLSX)**, **Download bank file (pain.001)** or **Download Electra file (.HUF)**.

AI Finance Team records a numbered payment file, marks each invoice "In payment file #N", and downloads the file. The spreadsheet has the payee, the account, the amount, the execution date and the invoice number on each row. You can key these into any netbank, or use your bank's own import if it accepts a spreadsheet. The bank file is pain.001.001.03 XML in the Hungarian HCT profile: import it in the netbank's file upload, check the lines and sign there. Every line carries the invoice number as the remittance text. The Electra file is the fixed-width "Forint átutalási megbízás" record; K&H e-bank accepts at most 40 lines per file, and the page refuses a larger selection.

The execution date is the due date, or the next banking day when the due date falls on a weekend, a public holiday, a rest day set by decree or in the past. Both formats use the same dates.

The list of files you generated is shown under the groups. **Download again** hands you the same file once more.

## Taking a line back

A payment file is a proposal, so sometimes the transfer does not happen: the file was never uploaded, the bank rejected the import, or nobody signed it. Switch on **Show lines already in a file**, find the line and click **Release**. Choose a reason (**Not uploaded**, **Rejected by the bank**, **Not signed** or **Other**) and the invoice goes straight back to the list of invoices to pay. **Release file**, in the list of files under the groups, does the same for every line of a file that is still waiting.

A line whose payment already arrived at the bank cannot be released, and releasing never changes the approval. On the invoice, the approval card then reads "Released from payment file #N" with the date and the reason.

A line marked **Not seen at the bank yet** was exported some time ago and no bank transaction has shown up for it. The page counts these at the top. It is information only: check the netbank, and release the line if the transfer was never made.

## How the payment finds its invoice

When the bank transaction arrives, AI Finance Team first looks among the lines it wrote into payment files. It knows the paying account, the payee's account, the exact amount and the date, so it can match the payment without any scoring. The match then reads **Matched from payment file #N**. If two exported lines could fit the same payment, the invoice id in the remittance text decides; if that does not settle it either, the normal matching takes over.

Everything else on the statement (customer receipts, tax, bank fees, transfers made by hand) is matched exactly as before.

## Questions people ask

**Can I pay an invoice that is not approved?** No. The list contains approved invoices only. Approve it first, or ask the finance admin to mark it as not needing approval.

**I generated a file by mistake.** Nothing happened in the bank. Simply do not import it, and release the file (see "Taking a line back") so the invoices return to the list at once.

**The amount is not what the invoice says.** The list shows what is still owed. A partially paid invoice shows the remaining balance, and Hungarian forint amounts are whole forints.
